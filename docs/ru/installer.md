# Установщик Yandex MCP для Linux

> Эта страница описывает прежний установщик Direct/Metrika. Для единого yandex-api-mcp используйте [новую инструкцию](unified-deployment.md).

[English instructions](../installer.md)

Этот [форк](https://github.com/5iNeX/yandex-direct-metrica-mcp) добавляет русский установщик и меню проектов к [исходному Yandex MCP](https://github.com/georgy-agaev/yandex-direct-metrica-mcp). Лицензия Apache-2.0 сохранена. У каждого пользователя — собственные OAuth и OpenAI Tunnel.

## Установка

Подойдут Debian 12/13 или Ubuntu 22.04/24.04, Python 3.10+, systemd, amd64/arm64. Нужны root/sudo и Docker Engine 28+ с Compose plugin. Можно использовать VPS, VM или LXC, в котором администратор уже разрешил запуск Docker.

```bash
git clone https://github.com/5iNeX/yandex-direct-metrica-mcp.git
cd yandex-direct-metrica-mcp
./install.sh --plan
sudo ./install.sh --install-deps
```

Сначала просмотри исходники. `--install-deps` устанавливает нужные пакеты. Если Docker отсутствует, добавляет подписанный официальный apt-репозиторий Docker и устанавливает Engine/Compose. Существующий Docker используется без удаления и автоматического обновления; нужна версия Engine 28+. Если в репозитории нет подходящего Compose plugin, скачивает официальный бинарный файл и проверяет SHA256. Такой plugin обновляется вручную; [инструкция Docker](https://docs.docker.com/compose/install/linux/).

Если Docker и Compose уже работают, можно убрать `--install-deps`. Для установки файлов без запуска мастера добавь `--no-setup`, затем выполни `yp setup`.

Установка по умолчанию — `/opt/yandex-mcp`. Можно задать `--prefix /srv/yandex-mcp` и другой `--port`. Родительские каталоги должны принадлежать root и быть защищены от записи другими пользователями. Существующий каталог и существующая команда `yp` не перезаписываются. Поддерживается одна общая команда `yp` на систему.

Установщик не создаёт Proxmox-контейнер, VPN или сетевые маршруты. Для macOS/Windows остаётся исходный `scripts/setup.py` для локальных MCP-клиентов.

## Первый запуск

Мастер последовательно предлагает:

1. Direct + Метрику, только Direct или только Метрику. Audience — по желанию.
2. Вход через своё OAuth-приложение Яндекса или ввод действующего токена.
3. OpenAI Tunnel для своего ChatGPT workspace.

### Яндекс

Создай своё приложение на [oauth.yandex.ru](https://oauth.yandex.ru/). Redirect URI по умолчанию: `https://oauth.yandex.ru/verification_code`. Включи необходимые доступы:

- `direct:api` — для Direct; приложению должен быть одобрен production/full API access.
- `metrika:read` — для Метрики.
- `audience:read` — если нужен Audience.

Client ID вводится локально; Client Secret, токены и код подтверждения — скрытым вводом. Открой выданную ссылку в браузере и вставь код либо полный redirect URL. Мастер сам обменяет код на токены через [OAuth с PKCE](https://www.yandex.ru/dev/id/doc/ru/codes/code-url). Для полного redirect URL проверяется `state`; при ручном вводе кода обмен защищает PKCE.

Учётные данные сохраняются в локальном `secrets/` с правами `0600`; каталог имеет права `0700`. Они не отправляются автору форка. API выбранных сервисов проверяются до переключения. После запуска нужен успешный `tools/list`. При сбое запуска восстанавливается прежняя конфигурация; кандидат остаётся защищённым, чтобы не потерять обновлённый refresh token. Повторить: `yp resume`.

При наличии refresh token ежедневный systemd timer обновляет токен по сроку, не реже чем после 75 дней. Для введённого access token без refresh token нужно повторить вход вручную. Мастер не отзывает прежний токен и не может выдать разрешение Яндекса на API.

### OpenAI

Мастер сначала проверяет доступ к `api.openai.com` и только затем запрашивает Tunnel ID и runtime API key с правами **Tunnels Read + Use**. Привяжи свой Tunnel к своему ChatGPT workspace и OpenAI organization. Ключ администратора организации вводить не нужно. [Официальная инструкция](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

Для tunnel-client можно указать существующий **HTTP/HTTPS CONNECT proxy**. В v0.0.15 SOCKS URL не поддерживаются; для SOCKS нужен HTTP CONNECT bridge из своей инфраструктуры. Proxy получает только процесс туннеля. Обычный маршрут сервера и Yandex MCP остаются прежними.

Tunnel-client скачивается из официального релиза с проверкой SHA256 либо копируется из уже установленного бинарного файла. Создаются отдельный systemd-пользователь, ограниченное sudo-правило для фиксированного stdio-wrapper и служба с автозапуском и `Restart=on-failure`. Ключи передаются через `LoadCredential`, в unit-файле их нет.

MCP слушает только `127.0.0.1:8000`. Health/UI туннеля — тоже loopback, по умолчанию порт 8080. Публичные порты и домен не нужны.

## Простая команда

```bash
yp
```

Русское меню позволяет:

- Найти доступные новые Direct-клиенты и активные счётчики Метрики.
- Добавить только Direct, только Метрику или связанный профиль.
- Добавить Direct по известному логину, если API не показывает делегированный кабинет.
- Связать добавленные профили после подтверждения.
- Убрать проект из локального реестра, посмотреть список и обновить MCP.

Реестр изначально пустой. Совпадение названий — только подсказка; связь подтверждает человек. Удаление проекта не удаляет данные в Яндексе. API Direct не перечисляет все делегированные кабинеты, а логин владельца Метрики не обязательно совпадает с логином Direct. При ручном добавлении Direct мастер проверяет чтение кампаний.

Перед изменением реестра сохраняется резервная копия. Одновременные операции `yp` блокируются. SSE и stdio-процессы используют один файл: SSE перезагружается явно, stdio обновляет реестр по времени изменения.

## Проверка и подключение ChatGPT

```bash
yp doctor
yp connector
```

`doctor` проверяет локальные SSE/stdio `tools/list`, реестр, `/healthz`, `/readyz` и `tunnel-client doctor`. Проверку удалённого клиента заверши в ChatGPT:

1. Settings → Plugins → создать developer-mode app.
2. Connection: **Tunnel**, указать свой Tunnel ID из `yp connector`.
3. Попросить ChatGPT вызвать `accounts.list` или показать инструменты.

Нужны доступный developer mode и разрешения администратора workspace. Подписи разделов могут отличаться. Это частное developer-подключение. Размещение приложения в публичном каталоге ChatGPT требует отдельной подачи и проверки.

## Обслуживание

| Команда | Что делает |
| --- | --- |
| `yp setup` | Продолжить первый запуск |
| `yp oauth` | Заново войти в Яндекс |
| `yp resume` | Повторить проверку сохранённого кандидата |
| `yp refresh` | Обновить токен, если подошёл срок |
| `yp --show` | Показать проекты без меню |
| `yp --discover` | Показать новые доступные записи |
| `yp --verify` | Обновить и проверить реестр |
| `yp tunnel` | Настроить ещё не настроенный туннель |
| `yp doctor` | Проверить MCP и туннель |
| `yp connector` | Показать шаги подключения |

Службы при стандартном имени проекта:

```bash
sudo systemctl status yandex-mcp-tunnel-yandex-mcp.service
sudo systemctl list-timers yandex-mcp-refresh-yandex-mcp.timer
sudo docker compose --project-name yandex-mcp --file /opt/yandex-mcp/compose.yaml ps
```

Не публикуй `docker compose config`, `docker inspect`, файлы secrets и дампы окружения: они могут раскрыть ключи. Резервные копии авторизации также содержат секреты и должны оставаться защищёнными. Установщик не удаляет пользовательские данные и не выполняет автоматические обновления исходников. Обновление — отдельное обслуживание с резервной копией.

## Границы первой версии

Мастер настраивает public read-only MCP: Direct, Метрику и необязательный Audience. Wordstat/Search API, Webmaster adapters, PRO-плагины и intelligence layer в него не входят. Исходные способы настройки MCP сохранены.

Тесты используют заглушки API. Docker smoke проверяет сборку, `tools/list` двух транспортов, обновление реестра и блокировку destructive Logs действий с тестовым токеном. CI не вызывает живые API. OAuth нового пользователя, его production-доступы и подключение его ChatGPT workspace проверяются при его установке.
