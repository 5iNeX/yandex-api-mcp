# Technical audit: webkoth/yandex-mcp and 5iNeX/yandex-direct-metrica-mcp

Date: 2026-09-30. Reviewed `webkoth/yandex-mcp` at commit `310369b32df2489035ef2603d71b92a678d70bbe` and the local fork at `6ee693a`. No live writes were used.

## Architecture options

1. Port Wordstat/Audience/Search and the Linux installer to TypeScript. This makes one runtime but rewrites working API clients and increases migration risk.
2. Keep Python as core and port all Webmaster/Direct/Metrika coverage from webkoth. This preserves deployment but duplicates the largest new surface and likely introduces endpoint errors.
3. **Chosen:** keep webkoth's TypeScript modules as the main functional core, retain the fork's Python read tools as an MCP child adapter, and expose one guarded gateway endpoint. This preserves both tested implementations and makes replacement of the adapter incremental. The cost is two runtimes in one container and one extra process boundary.

## Endpoint check

Official [Webmaster docs index](https://yandex.ru/dev/webmaster/doc/ru/llms.txt) and [authorization guide](https://yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth.md) were checked on 2026-09-30. Live smoke found that popular queries require `order_by` and broken internal links use `/links/internal/broken/{samples,history}`. Both core calls were corrected and verified live. The auth guide requires `webmaster:hostinfo` **and** `webmaster:verify`; the application and new token now have both, and host-level reads pass.

Direct uses the documented `POST https://api.direct.yandex.com/json/v5/{service}` and separate `/reports`, `Authorization: Bearer`, `Client-Login`, sandbox URL and `Units` header. The source project's [official API verification note](https://github.com/webkoth/yandex-mcp/blob/main/docs/superpowers/specs/2026-06-10-api-verification-official-docs.md) was cross-checked against live Direct requests. Empty `SelectionCriteria` is rejected for adgroups/ads/keywords; the caller must provide `CampaignIds` or another supported filter. Core tool descriptions now say so.

Metrika routes use `https://api-metrika.yandex.net/management/v1/...` and `/stat/v1/data`; counters, goals and reporting succeeded live. Wordstat `https://searchapi.api.cloud.yandex.net/v2/wordstat/`, Audience `https://api-audience.yandex.com/v1/management`, and Search API `https://searchapi.api.cloud.yandex.net/v2/web/` were validated by live read calls from LXC 123. Mutation endpoints were audited in source but not called against live accounts.

## Risks and decisions

- The shared OAuth state supports automatic refresh, but a *live* refresh was intentionally not forced while the old deployment uses the same refresh token; tests cover rotation and persistence with a mocked OAuth response. A live forced refresh could invalidate the old installation's token.
- The active project in webkoth core is process-global. Explicit `project` arguments are required for concurrent multi-project clients. Webmaster tools use explicit `host_id` but not project selection.
- The new SSE transport is localhost only and intended for local clients. The OpenAI Tunnel profile is unchanged pending Webmaster authorization and full read verification.
- The existing deployed Webmaster container is not proof of host-level API permission; the new live probe established partial access and the missing scope.
